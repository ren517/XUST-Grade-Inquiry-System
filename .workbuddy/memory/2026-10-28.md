### ✅ 已跑通：新入口完整链路（关键，以后直接照这个来）

教务系统自带 CAS 入口，藏得深但可用：

```
1. GET http://59.74.174.150/jwglxt/auth/auth_casAuthLogin.html
   → 302 http://jwsso.xust.edu.cn/auth/cas/login?service=<上面那个URL>
2. GET 该地址?login_type=normal&login_type_fragment=ImplNormal → 取 __token__
3. POST 该地址?login_type=normal  (username / password / __token__ / fingerprint)
4. 302 → auth_casAuthLogin.html?ticket=ST-xxx → ticketlogin?uid=&verify=&jsdm=xs → index_initMenu.html
5. session 里就有 JSESSIONID + route，check_login() 为 True
```

- 密码 AES-128-CBC + ZeroPadding，key = iv = `__token__` 前 16 位（每次变）。
- **必须 `session.trust_env = False`**：走系统代理时访问教务 CAS 端点返回 503，直连才 302。
- 教务各应用入口（成绩查询/课程表/选课…）都是该 CAS 入口加 `url=` 参数；列表来自门户接口 `app.php/portal/data_service/get_list?module=服务中心&type=教务应用`（需 access_token）。
- 实测（zzz / 24407120135）：登录 PASS、JSESSIONID PASS、check_login PASS、select_score 13 门课、Excel 导出、二次运行"Cookie有效"缓存复用，全部正常。

### 坑

- **零消耗探针**：构造"解密后为空"的密文（明文 16 个 `\x00`）提交，若服务端返回"密码不能为空"说明解密链路正确且不消耗失败次数；若返回"账号不存在或密码错误"说明 key 不对。服务端校验顺序是：密码判空 → 用户是否存在 → 密码比对。
- **加密正确性验证**：Python 加密 → Node 解密往返比对；或用 Node 加载站点自己的 JS（vm 模块）与标准实现对比。

- 新入口登录后把票据换回 jwglxt 会话的回调地址（ids 的 service / jwsso 的 authorize）未确认，需校内浏览器抓包后通过 `--service` / `--authorize` 或环境变量 `IDS_SERVICE` / `JWSSO_AUTHORIZE` 传入。
